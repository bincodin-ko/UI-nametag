# 파이썬과 C# 차이 (2026-10-20)

UI 이름표 프로그램을 무엇으로 만들지 고르면서 알게 된 것.

## 한 줄 요약
- **파이썬**: 빨리 만들어 "되나?" 확인하기 좋다. 짧은 코드, 많은 라이브러리.
- **C#**: Windows 프로그램을 제품처럼 매끄럽게 만들기 좋다. Windows 기본 기능을 바로 쓴다.

## 비교

| | 파이썬 | C# |
|---|---|---|
| 누가 만들었나 | 오픈소스 커뮤니티 | Microsoft (.NET) |
| 잘하는 일 | 자동화 스크립트, 데이터·AI, 빠른 시제품 | Windows 데스크톱 앱, 게임(Unity), 서버 |
| 코드 길이 | 짧다 | 더 길다 (형식을 정확히 적어야 함) |
| 실행 방식 | 실행할 때 한 줄씩 해석 → 시작은 쉽고 속도는 느린 편 | 미리 번역(빌드)해 두고 실행 → 빠르다 |
| 실수 잡기 | 실행해 봐야 오류가 나옴 | 빌드할 때 상당수를 미리 잡아 줌 |
| 준비물 | Python + `pip install 패키지` | .NET SDK + 프로젝트 파일(`.csproj`) |
| Windows 화면 기능 | 다른 사람이 감싸 놓은 라이브러리로 간접 사용 (예: pywinauto) | Windows 기본 기능 직접 사용 (UI Automation, 투명 창, 화면 캡처) |
| 화면(UI) 만들기 | tkinter·Qt로 흉내 → 화면 배율(125% 등)에서 어긋나기 쉬움 | WPF·WinUI → 배율·투명·테두리 깔끔 |
| 배포 | exe로 묶으면 큼 (30~80MB 예상) | 작고 정식 설치 파일 만들기 쉬움 |
| 쓰는 사람 PC | Python 환경 문제로 깨질 수 있음 | exe 하나면 끝 |

## 이 프로젝트에서 C#을 고른 이유
- 선택 레이어(마우스가 통과하는 투명 창)·테두리·이름표를 매끄럽게 그려야 함 → C# WPF가 기본으로 잘함
- picker, MCP 서버, 녹화를 **한 프로그램**에 넣으면:
  - AI가 `preview_plan`을 부르면 바로 화면에 그림 (파일 주고받기 없음)
  - `check_layout`이 UI Automation을 바로 읽음 (좌표 어긋남 없음)
  - 녹화는 Windows 기본 화면 캡처로 앱 창만, GPU 화면도 검게 안 찍힘
- 단점: 처음 만드는 데 더 오래 걸림, .NET SDK 설치 필요

## 비유
- 파이썬 = 조립식 키트. 금방 형태가 나오지만 이음새가 보인다.
- C# = 원래 그 집(Windows)의 공구. 손에 익히는 데 시간이 들지만 마감이 깔끔하다.

## 같이 알게 된 것
- WPF vs WinUI 3: 둘 다 C#으로 Windows 화면을 만드는 틀. WinUI 3가 더 새롭지만, 마우스가 통과하는 투명 창은 WPF가 쉽다.
- MCP 서버도 C#으로 만들 수 있다 (공식 SDK `ModelContextProtocol`).
